### Self-check

What could I have gotten wrong that VERIFY wouldn't catch?

1. **The bounded-drift tolerance (0.01%) is hand-set, not derived.** I picked 1e-4 = 2× the observed max. If the JOINT_USE_GUIDE's "<0.006%" qualitative bound is actually the right structural ceiling, then 0.01% is loose. Conversely, if NCHS occasionally produces 0.02% drift on specific years that we haven't seen yet, then 0.01% will produce false-positives. Mitigation: documented in DECISION_LOG 2026-05-13T03:00Z residual risk (a); the constant lives in one place (`_LINKED_NATALITY_DRIFT_TOLERANCE`) for easy tuning. **Risk: medium.**

2. **The B.4 documented-drops registry (`DOCUMENTED_DROPS`) is empty.** If any prior product release had documented row drops at parse/harmonize/derive boundaries that I missed (a release note buried in a subproject doc, not the main DECISION_LOG), the harness would silently FAIL on a future re-derivation that introduces those drops. Verified by `grep -r "documented_drop" .` returning no hits. Mitigation: the test infrastructure makes any future per-year mismatch loud; the maintenance cost is one dict update per documented drop. **Risk: low.**

3. **The B.5 "linked is subset of natality" framing was the wrong invariant.** I authored a strict subset assertion that the data violated; the surface invariant is bounded drift. Mitigation: surfaced via AskUserQuestion at DO halt; resolved with DECISION_LOG entry. **Risk: closed.**

4. **Session-scope fixtures may cache stale parquet state if the file mutates between two tests.** This is a pytest invariant (session-scoped fixtures read once per pytest session). If the parquet were re-derived mid-test-suite, downstream tests would see the old version. Not a real risk in CI (clean run per push) or local development (no concurrent re-derive during a pytest run). **Risk: low.**

5. **The `test_stratified_denominators_per_year_matches_natality` test asserts byte-exact agreement for 29 years.** If natality v2.8.0 had silently shifted per-year counts by even 1 record (a re-tabulation bug), this test would FAIL. Verified by direct run = PASS. Forward-looking: this test catches a future v2.9 natality regression where the stratified_denominators.csv (frozen at Task 1) and the natality parquet (mutated) diverge. **Risk: low / DESIRED behavior.**

6. **The 5 "linked > natality" drifted years (2005, 2006, 2008, 2011, 2012) are not directly individually pinned.** The bounded-drift invariant covers the envelope but doesn't record the exact per-year diffs. If a future linked-pipeline regression *recompresses* drifted years (e.g., 2005 drift drops from +228 to +0) AND simultaneously *introduces* new drift on different years (e.g., +228 in 2007), the bounded-drift check still passes as long as each year stays ≤ 0.01%. Mitigation: DECISION_LOG records the C8.4-authoring snapshot; Phase D / C8.11 cross-product COMPARABILITY consolidation may add a per-year drift baseline if needed. **Risk: low-medium.**

7. **The `test_canonical_join_keys_present_in_natality` test assumes natality v2.8.0 ships the canonical names natively.** If a future natality v2.9 reverts to v2.7 names (highly unlikely but possible), this test FAILs — and that's the right behavior (it forces a §11 plan-update on canonical_join_keys.py). **Risk: documented invariant, intentional.**
