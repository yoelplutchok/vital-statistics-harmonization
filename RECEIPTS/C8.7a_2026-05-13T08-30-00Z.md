### Self-check (§10 — what could I have gotten wrong that VERIFY wouldn't catch?)

1. **The audit collector matched on naming pattern, possibly missing path constants with unusual names.** Mitigation: the v2 collector widened from naming-pattern-only to "any single-Name module-level assignment with isolated Path-eval"; the false-positive rate is higher (e.g., OUT_SCHEMA caught) but the false-negative rate is near-zero modulo "Path-typed value not directly assigned to a Name" (which would be a non-idiomatic pattern). 2. **The "PASS" verdict for argparse-default-paths in natality `validate_linked_parquets.py` is potentially misleading**. The REPO anchor itself resolves; but the script's DEFAULT argparse values resolve to `natality/output/...` (broken). I labeled this as DOCUMENTED rather than PASS. A stricter reading would call it PARTIALLY-BROKEN. The verdict "DOCUMENTED" is consistent with the C8.7a scope-split (orchestrator + downstream-path concerns are C8.7b).
3. **The `subprocess.run(cwd=SUBPROJECT_ROOT)` rename in `run_pipeline.py`** changes behavior only when the script is invoked in a context where the SUBPROJECT_ROOT's parent dir is the monorepo (the patched case) — for the standalone-build invocation, SUBPROJECT_ROOT.parent IS the build dir, and the per-step scripts paths still resolve from `SUBPROJECT_ROOT/scripts/01_import/...`. The patch is forward-compatible with both layouts, but I haven't live-tested the standalone-build invocation post-patch. Defense: the patch is reversible via single revert; no consumer downstream has been pinned to the pre-patch SUBPROJECT_ROOT name (verified via `git ls-files | xargs grep -l 'run_pipeline.REPO_ROOT'` → no matches).
4. **`ALL_YEARS = 29` staleness is documented inline as a 3-line comment but NOT enforced as a test failure.** A future agent reading `run_pipeline.py` may treat the comment as informational and not surface it as a C8.7b prerequisite. Mitigation: the comment cites C8.7a/C8.7b by name, and `RECEIPTS/C8.7a_*.md` (this file) + `FIX_LOG.md` 2026-05-13T08:30Z entry + STATUS section explicitly carry it as a C8.7b PRE-FLIGHT item.

A test for "every symlink at `<MONOREPO>/output/` points at an existing target" would close this.
