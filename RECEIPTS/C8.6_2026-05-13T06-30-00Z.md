### Self-check

What could I have gotten wrong that VERIFY wouldn't catch?

1. **Cross-platform lockfile drift.** Locally-emulated VERIFY runs on macOS arm64 (`aarch64-apple-darwin`); live CI runs on linux-x86_64 (`ubuntu-latest`). The `uv.lock` is platform-aware but if a transitive dep has no linux-x86_64 wheel, `uv sync --frozen` will fail at the first CI run. **Mitigation:** documented as Forward-looking HALT #1; Phase D step 3 first push surfaces this if present. Fallback: `uv lock --python-platform linux` re-lock.

2. **Parquet-skip-in-CI weakens the green-check signal.** A clean Ubuntu runner has no parquets (gitignored sidecars to local build dirs); the conftest `_require()` skip-if-missing protocol will cleanly skip parquet-dependent tests. CI will report "N passed + M skipped" rather than the local "56 PASS + 1 XFAIL." A green CI tick under these conditions means "uv sync works + test collection succeeds + non-parquet tests pass" — weaker than the local baseline. **Mitigation:** routed to C8.13 (Performance + GitHub release artifacts) as the natural place to add a parquet-fetch step.

3. **Pinned action versions may go stale.** `actions/checkout@v5` and `astral-sh/setup-uv@v6` are current as of authoring (2026-05-13); GitHub's Dependabot or Renovate will surface upgrades. Major-version bumps may break behavior. **Mitigation:** routine maintenance; not a C8.6 scope concern.

4. **`uv` version pin `0.11.x` may resolve to a different patch on CI.** The local build runs `uv 0.11.10 (aarch64-apple-darwin)`; CI's `astral-sh/setup-uv@v6 (version: "0.11.x")` may install a newer 0.11.y. The lockfile is uv-format-version-stable so this is normally fine, but a bug-fix release could change behavior. **Mitigation:** pin to `version: "0.11.10"` if needed; accept the looseness for now to ease maintenance.

5. **The `pull_request` trigger has no fork-protection considerations.** A future PR from a fork would run CI with `secrets: false` by default (GitHub Actions security model); no secrets are needed here. If a future workflow adds a deploy step requiring secrets, the trigger needs hardening. **Mitigation:** acceptable for current scope.

6. **The locally-emulated VERIFY does not test the workflow's `astral-sh/setup-uv@v6` action behavior end-to-end.** Local emulation runs `uv lock --check` / `uv sync --frozen` directly against an already-installed uv; the action's setup behavior (download, cache-restore, Python install) is untested until first CI run. **Mitigation:** documented as part of Forward-looking HALT #1.

7. **YAML parsing edge cases.** PyYAML 6.0.3 parses bare `on:` as Python `True` (boolean) when unquoted; GitHub Actions accepts both forms. The SMOKE Tier 0 assertion handles both. If a future workflow uses YAML features that PyYAML and GitHub's parser disagree on (e.g., multi-document `---` separators, exotic anchors), local SMOKE may pass while CI fails. **Mitigation:** the workflow uses only canonical YAML; not a current risk.
