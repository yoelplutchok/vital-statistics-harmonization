### Self-check

What could I have gotten wrong that VERIFY wouldn't catch?

1. **B3 map decision for code 09**: I mapped 09 → null on the rationale that "All other Races" doesn't fit the 4-category bridged scheme. But NCHS may have a documented convention I'm unaware of where 09 should map to 4 (API) or 3 (AIAN). The 165 records affected (1989: 34; 1990: 72; 1991: 59) are a small fraction (0.087%) of V3a, but if the convention is "09 → bridged-API", race-stratified totals for V3a years would be off by ~165 cumulatively. Mitigation: documented prominently in `V3a_1989_1991_LAYOUT_DECISIONS.md`; user-guide control count (which is unbridged, using `TABFLG==2 AND RESTATUS!=4` without race stratification) doesn't depend on this choice and matches byte-exact. A future task could re-verify the bridged-race convention against an NCHS race-stratified table for 1989-1991 if such a table exists.

2. **version_flag synthesis for 1989-1991**: harmonize.py's V2-era branch sets `version_flag='S'` for 1989-1991 records (per the era="1992" → 1989-revision uniform convention). I extended the `if 1989 <= year <= 2002:` filter in `validate_external_v2.py` to apply the same version_flag='S' filter for 1989-1991. If version_flag was somehow not set to 'S' for V3a records (e.g., a derive.py edge case I haven't traced), `_v2_gte20_resident_count(harm, year)` would return 0 for the V3a years and the validator would FAIL — but it PASSES with 26/26. So version_flag is correctly synthesized as 'S' for V3a. Verified by validator passing.

3. **Other 1989-revision code-system differences**: I confirmed B1/B2/B4/B6 raw distributions are byte-identical between 1989-1991 and 1992 by direct value-distribution comparison. But the verification used the top ~15 most-frequent codes only. A long-tail unseen code in 1989-1991 (e.g., a sentinel code that NCHS retired between 1991 and 1992) would not have triggered the harmonize.py defensive halt because none was encountered during the full harmonize run. Risk: low (the harmonize covered all 188,909 V3a records without raising); confidence: high (no halt raised).

4. **L13-extension byte-position vs field-semantics**: I verified byte positions against the 1989/1990/1991 user guides via the page 5-6 Data Elements list cross-check. I did NOT verify each of the 197 fields' value semantics against each year's user guide individually (the MAGER vs MAGER41 lesson from V2.1). The strongest evidence that 1989-1991 fields are semantically identical to 1992 is the **canonical-filter aggregate match byte-exact** — if any of TABFLG / RESTATUS / OSTATE / DATAYEAR had different byte positions or value semantics in 1989-1991, the user-guide control count would not match (it's the canonical filter's output). All 3 controls match. This is strong but not exhaustive verification.
