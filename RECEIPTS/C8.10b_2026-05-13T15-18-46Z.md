The 34 cells found is consistent with the PRE-FLIGHT-computed count, so the workaround was correct for this session.

2. **The natality `preterm_lt37` bool aggregation `s.sum()` treats None as 0.** Pandas bool with NaN/None: `True.sum()` counts True only. My computation uses `n_known = notna().sum()` and divides preterm by known, which correctly excludes None-gestation births from both numerator and denominator. If `preterm_lt37` dtype silently changed from `bool` to `object` (string '0'/'1'/''), the `.sum()` would concat strings instead of counting True. **Mitigation**: the PRE-FLIGHT probe verified dtype=`bool` for natality and linked; the cache-cleared pytest 56P+1XF run includes `test_schema_dtype_parity.py` which gates on schema-CSV-vs-parquet dtype consistency. Any silent dtype drift would FAIL that test before reaching the notebook.

3. **The FD `gestational_age_combined` numeric cast in Section 3 swallows non-numeric values silently via `errors='coerce'`.** Per `pd.to_numeric(fd_t1['gestational_age_combined'], errors='coerce')`: any non-numeric value becomes NaN, then `.where(ga != 99)` further drops the documented "unknown" sentinel. If a future harmonization changed a sentinel from '99' to '88', my code would put those into the `under_20wk` or `early_20_27wk` bucket (depending on numeric value) silently. **Mitigation**: the conservation invariant `under + early + late + unknown == total` (asserted byte-exact for 2022) would catch a misclassification if it preserved totals; a per-year version of the conservation assert is a future hardening candidate (filed as C8.12 mutation-test candidate).

4. **The 0.01 pct-pt cross-product drift bound is rounded-rate-comparison artifact.** My computation rounds natality to 2 decimals and linked to 4 decimals; the bound 0.01 is in 2-decimal precision. If a future natality re-derivation introduced a 0.0001 systematic shift (below 2-decimal rounding) the test would still PASS. **Mitigation**: this is consistent with the C8.4-documented bound (DECISION_LOG 2026-05-13T03:00:00Z; max observed 0.0055%); per-year drift is also asserted in `tests/test_cross_product_join_parity.py::test_linked_per_year_count_within_drift_tolerance_of_natality` at row-count level. If a future hypothetical harmonization changed the semantics of `tabulation_flag` (e.g., introducing a new value '3' for late-revision states), the notebook would still use tab==2 and silently produce a different universe. **Mitigation**: the FD harmonized parquet currently has tabulation_flag values {1, 2}; the validator at `validate_external.py:121` is the authoritative consumer of the same filter.
