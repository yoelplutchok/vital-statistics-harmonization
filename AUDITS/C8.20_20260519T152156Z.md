int8/int16 recodes, bool→`true`/`false`, int codes — **0 collisions**) and for the
float32 `bmi_prepregnancy` (**0 collisions**), but is **lossy for the float64

- raw `1.027777` and `1.027778` → key `1.02778`
- raw `1.029095`, `1.0291`, `1.029103` → single key `1.0291` (3→1)

**Expected:** distinct source values render to distinct keys (or the loss is documented).
**Actual:** 72 keys each merge 2–3 distinct float64 `record_weight` values in the
`record_weight` (i) value-distribution panel and (iii) code-frame diff.

**Severity rationale — minor, not blocker/major:** confined to a single
genuinely-continuous NCHS sampling/adjustment weight (not a discrete code); **no
count corruption** (Check 2 passes across `record_weight`'s eras — collisions merge
keys but conserve totals); deterministic & reproducible (Check 5 passes); no
discrete code is hidden; the only visible artifacts are an undercounted long-tail
`_(+N more codes)_` and a continuous-weight "code frame" diff that is of marginal
analytic value anyway.

## AUDIT VERDICT: 1 FINDING(S)

**Bottom line.** C8.20's shipped numbers are sound: 100% of 96 independently
recomputed (variable,era) cells byte-match; per-era n conserves exactly across
every variable and equals independent rowcounts; the era partition closes exactly
over every parquet year with the linked gap being precisely {1992,1993,1994};
the builder is byte-deterministic across two full re-runs and the shipped docs
are exactly its output; all four parquet SHAs are byte-exact; scope is clean
(only the builder + 2 CODEBOOKs + 2 FAQs + smoke test + 3 named L11 scope notes;
no parquet/schema/metadata mutation; no FDA plan); every scope-note number
reconciles; and the SHAPE-only smoke harness provably bites on real regressions.
The **single finding is minor and non-blocking**: the `_fmt_val` 6-significant-
digit float format collapses 72 distinct float64 `record_weight` values into
shared table keys in the linked sub-appendix's `record_weight` panel/diff — a
representation-fidelity loss confined to one continuous NCHS weight, with **no
count corruption, no discrete-code loss, and full determinism**. No blocker
implies a bug in shipped C8.20, so no HALT is required. Because the audit charter
forbids modifying C8.20 artifacts, the finding is reported (not remediated) with
options for the human: (a) accept as a documented limitation for continuous-float
weights; (b) exclude continuous float64 weight columns from the value-distribution
panel; or (c) widen the float format (e.g. `repr`/`%.17g`) for float64 columns.
